### <a name="_qmphm5d6rvi3"></a>**Решение**
[Диаграмма контекста](context.puml)
[Диаграмма компонентов](component.puml)

Сервис с информацией о ставках позволяет направлять событие о изменении ставок в топик Kafka
Данный топик может слушать сервис передачи ставок и работать по 2 сценариям:
- По мере поступления изменений в топик - через REST API уведомлять CRM кол-центра об изменениях
- Раз в n-времени по кроне сгружать из топика изменения (, аггрегировать их и сохранять в виде Excel-файла на sFTP-сервере с доступом из партнерского кол-центра


### <a name="_bjrr7veeh80c"></a>**Альтернативы**
- Отправлять файл по почте, вместо sFTP
- Предложить партнерскому кол-центру интеграцию по REST API
- Напрямую интегрировать банковский кол-центр с Kafak и читать информацию на стороне CRM

**Недостатки, ограничения, риски**
- При использовании SFTP - нет гарантии доставки файла (нивелируется увеличением времени хранения сообщений в топике)
- Необходимость агрегировать данные при отправке партнерам, т.к. ставка по одному продукту может меняться несколько раз, нужно отправить самые актуальные данные
- Необходимость следить за offset-ом Kafka для сбора данных для партнеровпше
