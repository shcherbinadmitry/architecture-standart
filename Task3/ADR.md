### <a name="_qmphm5d6rvi3"></a>**Решение**
[Диаграмма контекста](context.puml)
[Диаграмма контейнеров](container.puml)
Для реализации функционала необходимо:
- Сервис управления депозитами
- Сервис управление ставками по депозитам

В качестве технологического стека выбран Java Spring Boot + PostgreSQL. Данный стек отлично зарекомендовал себя в решениях для крупных компаний + имеется экспертиза.
Для решения проблем с масштабирование, временем отклика - внедрен load-balancer, механизмы кеширования и новые микросервисы, которые возьмут на себя нагрузку с АБС
Т.к. применяется микросервисная архитектура, данные сервисы возможно масштабировать отдельно от АБС.
Для шифрования трафика все запросы из внешнего контура должны выполняться с применением HTTPS-протокола

**Недостатки, ограничения, риски**
- Переход на микросервисную архитектуру требует больших затрат на инфраструктуру
- Внедрение Kafka/Redis потребует времени на получение экспертизы/дополнительных затрат на найм
- Добавление API Gateway чревато единственной точкой отказа
- Внедрение асинхронного взаимодействия может повлиять на согласованность данных
